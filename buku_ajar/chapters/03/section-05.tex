\section{Lingkungan Run-Time: Static, Stack, dan Heap Allocation}
\label{sec:ch03-runtime}

\subsection{Tata Letak Memori Program}

Ketika program dijalankan, sistem operasi menyediakan ruang alamat
yang biasanya dibagi menjadi beberapa segmen: kode, data statis,
stack, dan heap. Segmen kode menyimpan instruksi. Segmen data statis
menyimpan variabel global dan konstanta. Stack menyimpan frame
aktivasi fungsi. Heap menyediakan memori untuk alokasi dinamis.

\subsection{Alokasi Statis}

Alokasi statis menempatkan variabel pada alamat tetap yang ditentukan
saat kompilasi. Variabel global, konstanta, dan variabel dengan
\code{static} biasanya dialokasikan secara statis. Keuntungannya,
akses cepat dan tidak ada biaya alokasi saat runtime. Kerugiannya,
ukuran harus diketahui saat kompilasi dan tidak mendukung rekursi
untuk variabel lokal.

\subsection{Alokasi Stack}

Alokasi stack dipakai untuk variabel lokal dan parameter fungsi.
Setiap pemanggilan fungsi mendorong satu \eng{activation record}
(frame) ke stack. Frame berisi parameter, variabel lokal, alamat
kembali, dan informasi lain yang diperlukan. Saat fungsi selesai,
frame dilepas. Model ini mendukung pemanggilan rekursif dan sangat
efisien.

\subsection{Alokasi Heap}

Heap dipakai untuk objek yang ukurannya tidak diketahui saat kompilasi
atau yang harus hidup melewati masa hidup fungsi. Alokasi dan
dealokasi dilakukan secara eksplisit (\code{malloc}/\code{free})
atau otomatis melalui pengumpul sampah (\eng{garbage collector}).
Heap lebih fleksibel, tetapi memiliki biaya: fragmentasi, waktu
alokasi, dan kemungkinan kebocoran memori.

\begin{contoh}[Activation record faktorial]
Untuk fungsi rekursif
\begin{lstlisting}[language=C]
int faktorial(int n) {
    if (n <= 1) return 1;
    return n * faktorial(n - 1);
}
\end{lstlisting}
setiap pemanggilan \code{faktorial} mendorong frame baru yang memuat
parameter \code{n} dan alamat kembali. Pemanggilan
\code{faktorial(3)} menghasilkan tiga frame bersarang sebelum
kembali. Setelah nilai kembali dihitung, frame teratas dilepas satu
per satu.
\end{contoh}

Pemahaman lingkungan run-time penting meskipun buku ini berfokus pada
front-end. Tanpa pemahaman ini, sulit menjelaskan mengapa informasi
scope, tipe, dan alamat perlu dipelihara sejak analisis semantik.
